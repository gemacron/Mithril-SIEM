🛡️ CÓMO CONECTAR UN PROXY NGINX A MITHRIL (PUERTO 9900)

Agente persistente con systemd y mitigación universal mediante Fail2ban Smart Action (compatible con o sin Cloudflare, sin tocar Nginx).

Fail2ban Smart Action Ubuntu 20/22/24 Rocky Linux 8/9 Cero Cambios en Nginx
💡 Recomendado: El script install_agent.sh detecta automáticamente si estás en Ubuntu/Debian o Rocky Linux/RHEL, instala y configura Fail2ban (con el jail mithril-jail y la acción universal mithril-smart), despliega el agente en memoria RAM y activa mithril-bouncer.service sin modificar ningún archivo de Nginx.
Paso 1: Clonar repositorio oficial en el proxy 
git clone https://github.com/gemacron/Mithril-SIEM.git /tmp/Mithril-SIEM
Paso 2: Ejecutar el instalador universal (Modo Interactivo) 
sudo bash /tmp/Mithril-SIEM/agent/install_agent.sh

* Te solicitará la URL del SIEM (http://{{ host_ip }}:9900) y el NODE_API_KEY que obtienes al crear el nodo arriba.

Alternativa: Instalación en una sola línea con Fail2ban (Automatizada / Ansible) 
sudo bash /tmp/Mithril-SIEM/agent/install_agent.sh "http://{{ host_ip }}:9900" "TU_NODE_API_KEY" "fail2ban" "15"
🛡️ Arquitectura Universal con Fail2ban (Sin tocar Nginx): Cuando haces clic en Aprobar Bloqueo en Mithril, el agente ejecuta fail2ban-client set mithril-jail banip <IP>. La acción inteligente mithril-smart bloquea la IP en el Kernel de Linux (ipset/iptables) para cualquier servidor sin Cloudflare o ataques directos a IP, y si detecta credenciales en /etc/mithril/cloudflare.env, bloquea simultáneamente la IP real en el borde de Cloudflare.
Paso 1: Instalar paquetes de Fail2ban e ipset (Ubuntu/Debian o Rocky/RHEL) 
# En Ubuntu / Debian:
sudo apt-get update && sudo apt-get install -y fail2ban ipset iptables curl

# En Rocky Linux / AlmaLinux / RHEL:
sudo dnf install -y epel-release && sudo dnf install -y fail2ban ipset iptables iptables-nft curl
Paso 2: Crear el filtro base y archivo de log de control 
sudo mkdir -p /etc/fail2ban/filter.d /etc/fail2ban/action.d /etc/fail2ban/jail.d /etc/mithril
sudo touch /var/log/mithril-fail2ban.log

sudo cat <<'EOF' > /etc/fail2ban/filter.d/mithril-empty.conf
[Definition]
failregex = ^MITHRIL_MANUAL_BAN <HOST>$
ignoreregex =
EOF
Paso 3: Crear la Acción Híbrida Universal (/etc/fail2ban/action.d/mithril-smart.conf) 
sudo cat <<'EOF' > /etc/fail2ban/action.d/mithril-smart.conf
[Definition]
actionstart = ipset create mithril_f2b hash:ip timeout 0 -exist
              iptables -C INPUT -m set --match-set mithril_f2b src -j DROP 2>/dev/null || iptables -I INPUT 1 -m set --match-set mithril_f2b src -j DROP

actionstop  = iptables -D INPUT -m set --match-set mithril_f2b src -j DROP 2>/dev/null || true
              ipset destroy mithril_f2b 2>/dev/null || true

actioncheck = ipset list mithril_f2b >/dev/null 2>&1

actionban   = ipset add mithril_f2b <ip> -exist
              if [ -f /etc/mithril/cloudflare.env ]; then . /etc/mithril/cloudflare.env; if [ -n "$CF_API_TOKEN" ] && [ -n "$CF_ZONE_ID" ]; then curl -fsSL -X POST "https://api.cloudflare.com/client/v4/zones/$CF_ZONE_ID/firewall/access_rules/rules" -H "Authorization: Bearer $CF_API_TOKEN" -H "Content-Type: application/json" --data "{\"mode\":\"block\",\"configuration\":{\"target\":\"ip\",\"value\":\"<ip>\"},\"notes\":\"Mithril-SIEM-Fail2ban\"}" >/dev/null 2>&1 || true; fi; fi

actionunban = ipset del mithril_f2b <ip> -exist
              if [ -f /etc/mithril/cloudflare.env ]; then . /etc/mithril/cloudflare.env; if [ -n "$CF_API_TOKEN" ] && [ -n "$CF_ZONE_ID" ]; then RULE_ID=$(curl -fsSL -X GET "https://api.cloudflare.com/client/v4/zones/$CF_ZONE_ID/firewall/access_rules/rules?configuration.target=ip&configuration.value=<ip>" -H "Authorization: Bearer $CF_API_TOKEN" -H "Content-Type: application/json" 2>/dev/null | grep -o '"id":"[^"]*"' | head -n1 | cut -d'"' -f4); if [ -n "$RULE_ID" ]; then curl -fsSL -X DELETE "https://api.cloudflare.com/client/v4/zones/$CF_ZONE_ID/firewall/access_rules/rules/$RULE_ID" -H "Authorization: Bearer $CF_API_TOKEN" -H "Content-Type: application/json" >/dev/null 2>&1 || true; fi; fi; fi

[Init]
name = mithril
EOF
Paso 4: Crear el Jail de Mithril (/etc/fail2ban/jail.d/mithril.local) y Activar Fail2ban 
sudo cat <<'EOF' > /etc/fail2ban/jail.d/mithril.local
[mithril-jail]
enabled  = true
filter   = mithril-empty
action   = mithril-smart
logpath  = /var/log/mithril-fail2ban.log
bantime  = -1
findtime = 600
maxretry = 1
EOF

sudo systemctl enable --now fail2ban
sudo fail2ban-client reload
sudo fail2ban-client status mithril-jail
Paso 5 (Opcional - Solo si usas Cloudflare): Configurar Token para bloqueo en el Borde de Cloudflare 
sudo cat <<'EOF' > /etc/mithril/cloudflare.env
CF_API_TOKEN="TU_CLOUDFLARE_API_TOKEN"
CF_ZONE_ID="TU_CLOUDFLARE_ZONE_ID"
EOF
sudo chmod 600 /etc/mithril/cloudflare.env

Comandos específicos para Ubuntu 20.04 / 22.04 / 24.04 LTS y Debian 11 / 12:

1. Dependencias del sistema (apt) 
sudo apt-get update
sudo apt-get install -y python3 fail2ban ipset iptables curl git
2. Archivo de servicio Systemd (/etc/systemd/system/mithril-bouncer.service) 
sudo cat <<'EOF' > /etc/systemd/system/mithril-bouncer.service
[Unit]
Description=Mithril SIEM Bouncer Agent
After=network-online.target fail2ban.service nginx.service

[Service]
Type=simple
User=root
Environment="MITHRIL_URL=http://{{ host_ip }}:9900"
Environment="NODE_API_KEY=TU_NODE_API_KEY"
Environment="BLOCK_METHOD=fail2ban"
Environment="FAIL2BAN_JAIL=mithril-jail"
Environment="SYNC_INTERVAL=15"
ExecStart=/usr/bin/python3 /opt/mithril-agent/mithril_bouncer.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
3. Iniciar y habilitar servicio persistente 
sudo systemctl daemon-reload
sudo systemctl enable --now mithril-bouncer.service

Comandos específicos para Rocky Linux 8 / 9, AlmaLinux, RHEL y CentOS Stream:

1. Dependencias del sistema (dnf + EPEL para Fail2ban) 
sudo dnf install -y epel-release
sudo dnf install -y python3 fail2ban ipset iptables iptables-nft curl git
2. Configuración SELinux (si aplica) 
sudo setsebool -P httpd_can_network_connect 1
3. Iniciar y habilitar servicio persistente 
sudo systemctl daemon-reload
sudo systemctl enable --now fail2ban mithril-bouncer.service

Con el Espejo de Red en RAM y Fail2ban, no necesitas modificar ni recargar Nginx para capturar tráfico ni para bloquear atacantes. Opcionalmente, puedes enviar logs JSON adicionales vía Syslog UDP (puerto 5140):

1. Formato JSON (pegar dentro de 'http { ... }' en /etc/nginx/nginx.conf) 
log_format mithril_json escape=json '{'
    '"client_ip":"$remote_addr",'
    '"real_client_ip":"$http_cf_connecting_ip",'
    '"x_forwarded_for":"$http_x_forwarded_for",'
    '"cf_ray":"$http_cf_ray",'
    '"cf_country":"$http_cf_ipcountry",'
    '"time_local":"$time_iso8601",'
    '"http_method":"$request_method",'
    '"uri":"$uri",'
    '"query_params":"$args",'
    '"status_code":$status,'
    '"bytes_sent":$body_bytes_sent,'
    '"latency_ms":$request_time,'
    '"user_agent":"$http_user_agent",'
    '"referer":"$http_referer"'
'};
2. Directiva opcional en el VirtualHost (dentro de server { ... }) 
# Envío directo al SIEM por Syslog UDP en tiempo real (sin tocar listas de bloqueo en Nginx)
access_log syslog:server={{ host_ip }}:5140,facility=local7,tag=nginx mithril_json;

Comandos de diagnóstico para monitorear el agente y los bloqueos aplicados por Fail2ban:

Estado del Servicio Systemd
sudo systemctl status mithril-bouncer
Registros de Telemetría en Vivo
sudo journalctl -u mithril-bouncer -f
Estado del Jail en Fail2ban
sudo fail2ban-client status mithril-jail
Ver IPs en Kernel (ipset de Fail2ban)
sudo ipset list mithril_f2b
